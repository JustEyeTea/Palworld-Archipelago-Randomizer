# Tools

Everything in `tools/`: the generators that write the repository's generated files, the build and the test runners,
two test clients for a live room, the modules the tools share, and the server probe that dumps the game's tables.
Each script's header has its exact command and says how it is tested. How the generated files fit into the project
is in [the architecture guide](../docs/architecture.md#generated-files).

## The private game files

Several generators read files made from the game, which are Pocketpair's and so never in this repository. Keep them
in a folder of your own, one per game version, laid out like this (`<refs>` below):

| Path | What it is | Made by |
|---|---|---|
| `<refs>/tables/` | the tables and actor lists the tools read, one `.tsv` each | the probe's `dumptable` and `dumpactors` commands |
| `<refs>/all-tables/` | every DataTable the game loads, all columns | the probe's `dumpalltables` command |
| `<refs>/map/WorldMap-2000.webp` | the world map picture, 2000 px | the mod's map export in game (`mapexport.lua`), scaled down |
| `<refs>/regions/regions.json` | every BP_PalRegionTrigger (the map rows' region volumes) of the main world | a dump of the server's pak |

Python: the Archipelago venv's python has numpy, Pillow and mapbox-earcut for the map tools; `lock_centres.py` and
`map_fields.py` need scipy, which it lacks, so run those with a python that has numpy, scipy and Pillow. The
others need only Python 3.11 or newer.

`<size>` is `region` (the 15 regions) or `area` (the 75 areas, with `LOCK_SIZE=areas` in the environment); `<v>` is
the game version's first three parts (`1.0.5`).

**After a game update**, in this order (each step reads what the one before wrote):
1. Dump the tables again with the probe, into a new `<refs>` folder.
2. For each size: `lock_walls.py`, then `lock_centres.py` and `map_fields.py`, then `lock_model.py`, naming the
   `data/` files with the new version.
3. `gen_apworld_data.py <new version> <refs>/tables <refs>/all-tables`, then `gen_lua_data.py`.
4. `gen_tech_icons.py` and `gen_tech_gifts.py`.
5. The tests below; `freeze_ids.py` only if the update added ids, and then read its diff.

## The build and the tests

| Tool | What it does | Private files |
|---|---|---|
| `build_apworld.py` | builds `palworld.apworld` as players get it, and checks it loads with its own version | no |
| `ap_tests.sh` | Archipelago's own test suites for this world, then `apworld/palworld/test/` | no |
| `test_generate.sh` | builds the `.apworld` and generates N seeds, each checked beatable | no |
| `test_options_page.py` | `options.json` is current, the page's YAMLs are Archipelago's templates word for word, and each generates a beatable seed | no |
| `lua_harness.sh` | the Lua mod's harness (`mod/test/harness.lua`), twice: plain, and with the probe and test tools on | no |
| `bridge_test.sh` | builds the connector's Archipelago bridge for Linux and runs it against a local room | no (needs the bridge's dependency clones in `DEPS`) |

The Archipelago tools take `AP_DIR`, your Archipelago folder with its venv in `.venv`. Without it they look for
`archipelago-<version>` beside this repository's folder (`ap_dir.sh`), which is wrong in a git worktree.

## Test clients (for a live room)

| Tool | What it does |
|---|---|
| `deathlink_send.py` | sends one Death Link to a room, signed with a name of its own, or (`--listen`) prints the room's Death Links |
| `send_checks.py` | checks a slot's locations by name, or lists its unchecked ones |

## Shared modules

| Module | What it holds |
|---|---|
| `lock_groups.py` | the 15 regions and 75 areas as groups of the game's map rows; `LOCK_SIZE` picks the set the map tools build |
| `towers.py` | the game's 13 tower bosses: number, boss type, the lock model's place, the goal tower's name |
| `table_dumps.py` | the reader of the table dumps, and the facts several tools read the same way from them |
| `apworld_loader.py` | loading the APWorld's tables or Archipelago's modules without Archipelago's loader; the Archipelago folder and version |
| `ap_dir.sh` | the shell scripts' default Archipelago folder |

## The probe

`probe/scripts/main.lua` is a UE4SS Lua mod for the Palworld dedicated server, not part of the mod players install.
It reads commands from `ue4ss/Mods/APProbe/inbox.txt`; `dumptable`, `dumpactors` and `dumpalltables` write the
`.tsv` files above into `ue4ss/Mods/APProbe/out/`. Its header lists the other commands.

## The Archipelago version

The version the APWorld targets is kept once, as `minimum_ap_version` in `apworld/palworld/archipelago.json`; the
tools and the release notes read it there. The copies that can't read it, to change with it:
- `.github/workflows/ci.yml`: the apworld job's matrix (a step there fails when it differs from archipelago.json);
- `README.md`: the version it targets and the example `AP_DIR` commands;
- `.github/ISSUE_TEMPLATE/bug_report.yml` and `generation.yml`: the placeholder version;
- `docs/options/options.json`: its `archipelago_version`, written by `gen_options_page.py` from the Archipelago in
  `AP_DIR`.
