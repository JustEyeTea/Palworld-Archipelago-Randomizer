# Tools

Everything in `tools/`: the generators that write the repository's generated files, the build and the test runners,
two test clients for a live room, the modules the tools share, and the server probe that dumps the game's tables.
Each script's header has its exact command and says how it is tested. How the generated files fit into the project
is in [the architecture guide](../docs/architecture.md#generated-files).

## The private game files

Several generators read files made from the game, which are Pocketpair's and so never in this repository. Keep them
in a folder of your own, one per game version, laid out like this (`<refs>` below):

| Path | What it is | Made by |
|---|---|---|
| `<refs>/tables/` | the tables and actor lists the tools read, one `.tsv` each | the probe's `dumptable` and `dumpactors` commands in [`probe/commands.txt`](probe/commands.txt) (see [The probe](#the-probe)) |
| `<refs>/all-tables/` | every DataTable the game loads, all columns | the probe's `dumpalltables` command |
| `<refs>/map/WorldMap-2000.webp` | the game's world map picture, 2000 px square | the mod's saved colour map, scaled down (see [The map picture](#the-map-picture)) |
| `<refs>/regions/regions.json` | every `BP_PalRegionTrigger` (the map rows' region volumes) in the main world | a pak-reading tool kept outside the repository (see [The region volumes](#the-region-volumes)) |

### The map picture

`lock_walls.py` tells land from water by the game's own world map. The mod saves that map the first time the world
map opens (`map_picture.lua`, `COLOUR_FILE`), so:
1. Install the mod with no other mod that changes the world map, keep the map settings in config.txt at their
   defaults, connect to a seed with Area Locks on, and load its world.
2. Open the world map once. UE4SS.log says `map: saved the colour map <path>`: the file is `map-colour-1.png`
   (4096 x 4096 px) in the mod's folder, `Pal/Binaries/Win64/ue4ss/Mods/PalworldArchipelago/`.
3. Scale it to 2000 px with any Python that has Pillow:

   ```
   python3 -c "from PIL import Image; Image.open('map-colour-1.png').convert('RGB').resize((2000, 2000), \
   Image.LANCZOS).save('<refs>/map/WorldMap-2000.webp', lossless=True)"
   ```

Untested: the picture in use was exported by an earlier test build. `map-colour-1.png` is the same game texture drawn
whole, so it should give the same land and water, but compare `lock_walls.py`'s output with the files in the
repository (`git diff`) before trusting a new one.

### The region volumes

`regions.json` comes from the game's pak files, not from the running game, so the probe can't make it. The tool that
makes it (a C# program on CUE4Parse, and a Python step that turns its dump into `regions.json`) reads Pocketpair's
files and is kept with the private references, outside this repository. To run it again you need:
- the .NET SDK and the CUE4Parse package;
- the game's `Pal/Content/Paks/` folder;
- the game's mappings file (`.usmap`), from the probe's `dump` command (UE4SS's `DumpUSMAP`);
- the Oodle compression library CUE4Parse reads the paks with;
- `<refs>/all-tables/` (`DT_WorldMapAreaData.tsv` and `DT_WorldMap_Common_Text_Common.tsv`), for the areas' names.

A game update that moves no region volume needs no new `regions.json`: copy the last version's.

### Python

The map tools need numpy, Pillow and mapbox-earcut 1.0.3, which Archipelago's venv does not come with. Install them
into it once: `<AP>/.venv/bin/pip install numpy Pillow mapbox-earcut==1.0.3`. `lock_centres.py` and `map_fields.py`
also need scipy; run those with any Python that has numpy, scipy and Pillow. The other tools need only Python 3.11 or
newer.

`<size>` is `region` (the 15 regions), `area` (the 75 areas, with `LOCK_SIZE=areas` in the environment) or `level`
(Level Progression's tiers, with `LOCK_SIZE=levels`); `<v>` is the game version's first three parts (`1.0.5`).
Level Progression's commands, as an example of one size (the others drop `LOCK_SIZE` or set it to `areas`, and name
their own files):

```
LOCK_SIZE=levels <AP venv python> tools/lock_walls.py <refs> mod/PalworldArchipelago/Scripts/level_walls.lua \
    <level grid .npz> <level overlay .png>
LOCK_SIZE=levels python tools/lock_centres.py
python tools/map_fields.py mod/PalworldArchipelago/level_labels.png mod/PalworldArchipelago/level_field.png
LOCK_SIZE=levels LOCK_GRID=<level grid .npz> <AP venv python> tools/lock_model.py <refs>/tables \
    data/level-model-1.0.5.json data/level-pal-sources-1.0.5.json <level pieces .png>
```

**After a game update**, in this order (each step reads what the one before wrote):
1. Dump the tables again with the probe, into a new `<refs>` folder; make a new map picture and `regions.json` only if
   the game's map or region volumes changed.
2. For each size: `lock_walls.py`, then `lock_centres.py` and `map_fields.py`, then `lock_model.py`, naming the
   `data/` files with the new version. After the areas: `wall_region_variants.py`.
3. `gen_apworld_data.py <new version> <refs>/tables <refs>/all-tables`, then `gen_lua_data.py`.
4. `gen_tech_icons.py` and `gen_tech_gifts.py`.
5. The tests below; `freeze_ids.py` only if the update added ids, and then read its diff.

## The build and the tests

| Tool | What it does | Private files |
|---|---|---|
| `build_apworld.py` | builds `palworld.apworld` as players get it, and checks it loads with its own version | no |
| `ap_tests.sh` | Archipelago's own test suites for this world, then `apworld/palworld/test/` | no |
| `test_generate.sh` | builds the `.apworld` and generates N seeds, each checked beatable | no |
| `test_options_page.py` | `options.json` is current, the page's YAMLs are Archipelago's templates word for word, and each generates a beatable seed | no |
| `lua_harness.sh` | the Lua mod's harness (`mod/test/harness.lua`), twice: plain, and with the probe and test tools on | no |
| `cpp_tests.sh` | the APConnector's Linux tests (`cppmod/APConnector/test/`), built with g++, then `check_lua_api.sh`; CI runs the same script | no |
| `bridge_test.sh` | builds the connector's Archipelago bridge for Linux and runs it against a local room | no (needs the bridge's dependency clones in `DEPS`) |

The Archipelago tools take `AP_DIR`, your Archipelago folder with its venv in `.venv`. Without it they look for
`archipelago-<version>` beside this repository's folder (`ap_dir.sh`), which is wrong in a git worktree.

## Shared modules

| Module | What it holds |
|---|---|
| `lock_groups.py` | the 15 regions and 75 areas as groups of the game's map rows, and Level Progression's tier bands; `LOCK_SIZE` picks the set the map tools build |
| `level_tiers.py` | Level Progression: the land labelled by its Pals' level, and the water lanes and flying corridors to walled-in tiers (flown when the sea way round is far longer) (used by `lock_walls.py`) |
| `flying_picture.py` | Level Progression: the flying corridors as `level_flying.png`, for the C++ part's map (used by `lock_walls.py`) |
| `grid_cells.py` | the map tools' grid and the steps on it they share (`lock_walls.py`, `level_tiers.py`) |
| `towers.py` | the game's 13 tower bosses: number, boss type, the lock model's place, the goal tower's name |
| `table_dumps.py` | the reader of the table dumps, and the facts several tools read the same way from them |
| `apworld_loader.py` | loading the APWorld's tables or Archipelago's modules without Archipelago's loader; the Archipelago folder and version |
| `ap_dir.sh` | the shell scripts' default Archipelago folder |

## The probe

`probe/scripts/main.lua` is a UE4SS Lua mod for the Palworld dedicated server on Windows, not part of the mod players
install. To use it:
1. Copy `tools/probe/scripts/main.lua` to `Pal/Binaries/Win64/ue4ss/Mods/APProbe/Scripts/main.lua` in the server's
   folder (the folder must be named `APProbe`: the probe reads its paths under that name), and add an empty
   `enabled.txt` beside `Scripts`, so UE4SS starts it.
2. Start the server and load its world. UE4SS.log says `[APProbe] polling ue4ss/Mods/APProbe/inbox.txt`.
3. Write commands into `ue4ss/Mods/APProbe/inbox.txt`, one per line. Every 2 s the probe runs the lines there,
   empties the file and logs each as `[APProbe] command: ...`.
4. Its files land in `ue4ss/Mods/APProbe/out/`.

The commands that make `<refs>/tables/` are in [`probe/commands.txt`](probe/commands.txt): paste them into the inbox
as they are, then copy `out/` to `<refs>/tables/`. `dumptable <table path> <column> ...` writes one table's columns
as `out/<table>.tsv`; `dumpactors <class> <field> ...` writes every loaded actor of a class, with its place and
bounds, as `out/actors_<class>.tsv`. `dumpalltables` writes every loaded DataTable, all columns, into `out/` too (not
into the `out/all/` folder it makes), so run it after copying the tables away, then copy `out/` to
`<refs>/all-tables/`. The probe's header lists its other commands; `props <class> <field> ...` logs fields of the
first live object of a class.

## The Archipelago version

The version the APWorld targets is kept once, as `minimum_ap_version` in `apworld/palworld/archipelago.json`; the
tools and the release notes read it there. The copies that can't read it, to change with it:
- `.github/workflows/ci.yml`: the apworld job's matrix (a step there fails when it differs from archipelago.json);
- `README.md`: the version it targets and the example `AP_DIR` commands;
- `.github/ISSUE_TEMPLATE/bug_report.yml` and `generation.yml`: the placeholder version;
- `docs/options/options.json`: its `archipelago_version`, written by `gen_options_page.py` from the Archipelago in
  `AP_DIR`.
