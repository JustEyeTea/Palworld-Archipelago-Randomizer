# Style guide

How code in this repository is written, so that a person can read it, understand it and change it by hand. It builds
on [Archipelago's style guide](https://github.com/ArchipelagoMW/Archipelago/blob/main/docs/style.md), which applies
everywhere it has a rule (120-character lines, Python PEP 8 with double quotes, Markdown, HTML, CSS, JS). Where this
guide says more, it wins. How the parts fit together is in [the architecture guide](architecture.md).

Most of this code is written by Claude, an AI model made by Anthropic, at JustEyeTea's direction. These rules exist so
that its maintainer, and anyone else, can follow every file without having written it.

Some files break these rules today. Each is fixed when the code tour reaches it; until then, new code follows the
rules and old code is not made worse.

## Naming

- **Say what it is in words a player would recognize.** Use `tower_level`, not `tl`. Use game terms (Area Pass,
  Paldeck, alpha, fast-travel point) the way the game and this project's docs use them. A *region* is one of the 15
  large locked parts, an *area* one of the game's 75 named places, and a *lock* either one, in code that serves both
  sizes alike; the full list is under [Words](architecture.md#words).
- **Read fields by name, never by position.** Write `tech.level`, not `tech[2]`. Give a row of data a `NamedTuple`
  (Python) or a table with named keys (Lua).
- **Define in-house words once.** Words this project made up, such as *piece* (the smallest part of the map the logic
  knows) or *sphere tier*, are defined in a comment where they are first used.
- **One word per thing, and one thing per word.** A thing keeps one name in every file (`opening`, not also
  `sinking`). A name is not used for a second thing in the same file. A name says what the value is now, not what
  it once was. Code that ships to players is never called `probe`, `test`, `old` or `tmp`.
- **Single letters** are only for a short loop's index or a coordinate (`x`, `y`, `u`, `v`).
- **Constants** are `UPPER_SNAKE_CASE`, with a comment giving the unit and the reason:
  `FREE_LEVEL = 15  # levels anyone reaches in the starting zone`. A constant is written once and imported; it is
  not typed again in another file. Where a copy cannot be avoided (another language, text the player reads, a
  build script), the comment names every copy, and a test compares them where it can. A name in upper case is
  never assigned a second time: a value that changes while the game runs is state, and is written in lower case.
- **Game ids get their name beside them.** For example, `"Product_Ingot_Grade_03_Steal"  # Refined Ingot`. Many of
  the game's ids differ from what the game shows.

## Comments

- **Say why, not what, and never when.** The code says what it does. A comment says why it does it that way, or what
  would go wrong otherwise.
- **History belongs in commit messages:** dates, version numbers, quotes from playtests, "was X before". A comment
  describes the code as it is now and must stay true when the code changes.
- **Every file opens with 1-5 lines on its job.** Every function others call has a one-line description of what it
  does.
- **Mark what is untested in game,** as "untested in game", and say exactly which behaviour the mark covers. Each
  such fact has one home, beside the code it is about; other files point there and do not repeat it. Remove the
  mark when a playtest confirms the code works.
- **Generated files open with "Generated by <script> from <source>; do not edit by hand."**

## Building blocks

Shared pieces that every part of this project uses. Before you write a helper, a wait, a kept variable, a text format
or a new file, look here and use the block. Never write a second copy. A block is listed here once it exists.

- **A log line, a log-once, a guarded call, an object's address:** `log`, `once` (`onceIn(owner)` for a module's
  own keys), `onceErr`, `safe`, `addr` in `util.lua`. A failure that can repeat every update goes through
  `onceErr`. Which branch of a fallback ran: `took`.
- **A texture or other object the game must not free while the mod uses it:** `keepAlive(obj)`, or
  `keepInPlace(index, obj)` for a picture made again and again, in `util.lua`.
- **A wait:** `updates(seconds)` from `util.lua`, as a named entry in the file's `WAIT` table (the core files share
  `clock.lua`'s). Never a bare count of updates, and never a typed 300 or 0.3. A schedule ("every 3 seconds") is
  tested with `isDue`. A log line that says how long turns a count of updates back into seconds with
  `CLOCK.seconds`.
- **The time in the core:** `CLOCK.now()`, the update count, from `clock.lua`. Timed work in the core is a phase in
  `PHASE` and a row in `main.lua`'s `PHASE_STEPS`, never a test of the count inside another step.
- **The Archipelago state:** the table `ap` in `ap_state.lua`, each field with when it is forgotten. Only
  `STATE.setStatus` writes the connection's state; a new seed's forgetting is `STATE.forgetSeed` plus one reset per
  topic, called from `connection.lua`'s `resetSeed`.
- **This update's player:** the frame record from `player.lua` (`PLAYER.lookUpFrame`, once per update), read with
  `PLAYER.playerState()`, `playerPawn()` and `pawnXY(pawn)`. A notice in chat is `PLAYER.notify(text)`.
- **A core file:** it takes the other core files with `require`, and what only `main.lua` can give (the mod's
  folder, the version) through `install(env)`, listed in its header; its kept state is in a block that says when
  each field is forgotten. A start-up step is a named function in `main.lua`'s start-up list.
- **A function the Lua mod calls in the connector:** `register_text` in `dllmain.cpp`. Code that turns text into
  numbers lives in `lua_text.*`, which is tested on Linux. An event line the bridge sends Lua is built and taken
  apart in `event_lines.*`.
- **Which world the player is in, and forgetting the last one:** the world step in `world.lua`. `WORLD.note()` runs
  near the start of every update; `WORLD.key()`, `WORLD.age()` and `WORLD.settled()` answer for every file. A file
  that keeps anything from one world registers the function that forgets it with `WORLD.onChange(forget)`, in
  `main.lua`'s start-up list. New code keeps no world key of its own (`mailbox.lua` and `menu.lua` still notice a
  world change themselves).
- **A hook callback:** wrapped by `guardedHook(name, cb)` from `util.lua`, so no core update runs inside it and an
  error is logged once under the hook's name.
- **A hook on a Blueprint class:** `hookWhenLoaded(path, fn, tag)` in `util.lua`, called every update until it
  registers.
- **A harness test:** a `group(title, function() ... end)` in the file of `mod/test/tests/` for its topic, added at
  the end of the group it extends (groups run in order and share the state they leave). Set the scene through the
  stand-ins: a switch in `game` (declared in `fakes.lua`'s `GAME_START`), a world helper (`inWorld`,
  `newController`, `newPawn`), or a field of a fake; a new stand-in goes in the fakes file of its topic
  (`fakes.lua`, `fakes_map.lua`, `fakes_menus.lua`), beside the lookup that returns it. Send events with `pushItem`,
  `pushScout`, `trap` and `push`, and move time with `run`, `runCycles`, `runSeconds` and `runPast(WAIT.<wait>)`,
  never a typed count of a wait. Check with `expect(cond, "what should be true: " .. tostring(value))`, one
  behaviour per check; ask the log about one step with `logMark()` and `loggedSince(mark, pattern)` (`logged` looks
  at the whole run). A helper two groups need goes in `helpers.lua` as `h.<name>`; a value a later group needs goes
  in `shared`. The steps are in the header of `mod/test/harness.lua`.

## Failures and fallbacks

- **Nothing fails or falls back in silence.** Code that gives up, skips a row or takes its second choice says so
  once, and names what it was working on (the path, the id, the row) and the reason. In the Lua mod that is a log
  line. In the APWorld it is an error or `logging.warning`. In the connector it is a `status error` event line or
  a log line.
- **A chain over a fixed set of kinds names every kind and ends in an error,** never in an `else` that quietly
  stands for "the rest".

## Size and layout

- **A function does one job and fits on one screen:** aim for 40 lines or fewer and no more than 3 levels of nesting.
- **A hand-written file has one topic:** aim for 800 lines or fewer. `mailbox_chest.lua` is over this and gets split
  by topic when the tour reaches it.
- **One statement per line,** and no `;` joining two. An `if`, `for` or `while` puts its body on its own lines.
  The one exception is a guard clause whose whole body is `return` (with or without a value), `break` or
  `continue`: `if not pawn then return end` (Lua), `if (!m_client) return;` (C++).
- **No bare numbers with a meaning.** Give each one a named constant. `0`, `1` and an obvious `2` are fine.
- **One way per job.** Where a file already does a job one way (wiring a module, registering a hook, starting a
  background job, reading a number from text), new code does it the same way. Two ways side by side need a comment
  that says why they differ.
- **Delete what nothing reads:** a function, parameter, field, export or stand-in with no user. If it is kept for
  a test or a probe, a comment beside it names that user.
- **Repeat with code, not by typing:** `range(1, 33)`, not the numbers 1 to 32 written out.

## Lua (UE4SS)

UE4SS runs some callbacks on a different thread from the game, over the same Lua state, and Lua code there corrupts
that state. These rules keep the mod's code on the game thread. The harness checks the first three
(`mod/test/tests/rules.lua`).

- **Never use `ExecuteWithDelay`.** For work later, use the queue in `soon.lua` (`later(n, fn)` runs `fn` after `n`
  core updates).
- **Every key bind only hands off:** `RegisterKeyBind(key, function() ExecuteInGameThread(onKey) end)`, with
  `onKey` built once, when the file loads.
- **`LoopAsync` only hands off, and at 300 ms or slower.** The callback is `ExecuteInGameThread(work)` and nothing
  else.
- **Don't keep game objects across a world change.** Look them up again after loading a world. A handle from the old
  world points at freed memory.
- **Log with the `[PalworldAP]` prefix,** and say what the code found, not just that it ran.
- **Every bug found in game becomes a harness test** that reproduces the game's side of it.

## C++

- **Keep the parts that need no Unreal in their own files** (`ap_bridge.*`, `event_lines.*`, `lua_text.*`,
  `pal_gift_logic.*`, `image_tools.*`), so they are tested on Linux (`cppmod/APConnector/test/`).
- **Functions the Lua mod calls take and return text,** and are listed with their arguments at the top of
  `dllmain.cpp`. Each is registered through `register_text` there; code that turns text into numbers lives in
  `lua_text.*`.

## Tests and commits

- **Run the tests before committing:** `tools/ap_tests.sh` for the APWorld, `tools/lua_harness.sh` for the Lua mod,
  and `tools/test_options_page.py` after any change to the options or the APWorld's version (it checks
  `docs/options/options.json` is current and that every preset makes a beatable seed). CI builds and tests the C++.
  Judge a run by its exit code, not by reading its output.
- **Ids never move** (see [Ids never move](architecture.md#ids-never-move)). `test/test_ids.py` enforces it.
- **A change that only makes code clearer** starts its commit message with `readability:` and changes no behaviour.
  The tests prove it; for the APWorld, the same seed must also give the same spoiler log before and after, up to its
  Playthrough section, which can pick a different (equally valid) chain from run to run even with no change. (Renaming
  an item is the exception: Archipelago sorts the item pool by name before shuffling, so new names place items
  differently. Then compare the location list and the item pool, which must match apart from the names, and check
  the seed is still beatable.)
- **Pocketpair's data stays out of the repository:** no table dumps, textures or maps. Commit the generators, and
  make the data from your own copy of the game.
- **Say plainly when work is AI-written,** in docs and release notes.
